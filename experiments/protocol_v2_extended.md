# Розширення порівняння v2: сортування лише за важливістю

Цей протокол зафіксовано до запуску нового восьмого методу. Попередні результати
v2 вже відомі; розширення є додатковим аналізом на тому самому наборі, а не новою
незалежною перевіркою. Набір `results_v2/inputs.jsonl` копіюється без зміни байтів.

1. Використати всі 1440 збережених сценаріїв v2 без відбору й нового генерування.
   Зберегти всі сім попередніх методів; додати `importance`, який ранжує за
   нормованою важливістю `(p−1)/4`. Терміновість та історія не входять до його
   оцінки. Спільні правила розв'язання нічиїх і календарні обмеження зберігаються.
2. Перед запуском перевірити SHA-256 конфігурації, входів, планів, CSV v2 та коду,
   збереженого в `experiments/frozen_v2/recommender.py`. Файли v2 не змінювати.
3. Для кожного сценарію всі вісім методів отримують однакові публічні входи.
   Приховані тривалості використати тільки після побудови планів для оцінювання.
4. Кожний метод прогріти одним викликом. Виконати три вимірювані виклики на метод
   і сценарій, змінюючи порядок фіксованим генератором. Показник часу для сценарію
   є медіаною цих трьох вимірювань. Він не включає БД, агрегацію історії й оцінювання.
5. Зіставити всі поля призначень, причини відмов і кількість кандидатів семи старих
   методів зі збереженими результатами v2. Перевірити незалежним валідатором усі
   обмеження кожного плану. За невідповідності завершити запуск із помилкою.
6. Зберегти первинні метрики v2. Додатково обчислити для кожного сценарію відношення
   суми початкових важливостей p запланованих задач до такої суми для EDF. Якщо
   знаменник нульовий, значення не визначено; не замінювати його довільним числом.
   Середнє цих відношень і відношення сум за всіма сценаріями є різними метриками
   й у підсумковій CSV отримують різні назви.
7. Не змінювати ваги, параметри генерації або нечіткі правила за результатами.
   Жодного доступу до робочої БД або надсилання листів. Нові результати записати
   в окрему папку `results_v2_extended`, зберегти код, конфігурацію та контрольні суми.

Вхідні 1440 сценаріїв залишаються 1440 незалежними наборами. Повторні вимірювання
часу й додавання восьмого алгоритму не збільшують цю кількість. Порівняння стосується
синтетичної моделі та не вимірює фактичну продуктивність користувачів.
